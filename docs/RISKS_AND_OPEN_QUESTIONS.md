## D. Provider Dependencies
Gemini, OpenAI, Anthropic, Groq, Sarvam are evaluation candidates; **capabilities, pricing, model names, regional availability, and data-retention terms were not verified in Phase 0** and must be checked against current official documentation before Phase 6. Sarvam AI is of particular interest for Indic languages; its STT/LLM streaming support and latency need PoC. Each provider's terms regarding sending resumes/transcripts (personal data) must be reviewed; prefer zero-retention/no-training settings.

## E. Latency Risks
LLM first-token varies by provider/model/load; STT finalization delay; screenshot vision calls are slowest; cold starts on serverless; network RTT from user to region. Plan: measure per-stage, choose fast-tier models for classification/answers, region placement, keep-alive connections, fallback on first-token timeout.

## F. Audio Capture Limitations
- Windows: system/loopback audio via WASAPI is feasible; per-app capture limited by OS version.
- macOS: system audio requires ScreenCaptureKit (macOS 13+) or virtual driver; Screen Recording/Microphone permissions required and user-visible.
- Linux: PulseAudio/PipeWire monitor sources; Wayland restrictions on screen/portal access.
- Echo/feedback if user uses speakers; headset assumed best; noise, overlapping speech, compression artifacts from video-call apps reduce accuracy.
- Browser-based calls vs. desktop apps behave differently. Needs PoC per OS.

## G. Platform-Specific Desktop Limitations
Always-on-top/overlay behavior over fullscreen apps differs per OS (macOS Spaces, Windows exclusive fullscreen); click-through and transparency vary by webview; global hotkey conflicts; code signing/notarization requirements; auto-update; Tauri webview version differences (WebView2/WKWebView/WebKitGTK). Screen-capture permission prompts cannot and should not be bypassed.

## H. Privacy, Security, and Policy Considerations
- **Acceptable use / integrity:** Tools that assist during live interviews may violate some employers' or interviewers' rules and, depending on jurisdiction, recording/transcribing other parties may require consent. The product must be authorized and user-controlled, with clear on-screen capture indicators, no stealth/anti-detection features, and an acceptable-use acknowledgement. **Legal/policy review needed (OQ-15, OQ-11).**
- Personal data (resumes, transcripts, screenshots) is sent to third-party AI providers: need data-processing review, minimization, retention limits, and user disclosure.
- Screenshots may incidentally capture third-party/confidential data: short retention, user-visible preview before upload (consider), deletion controls.
- Compliance (e.g., India DPDP, GDPR if applicable) must be assessed by qualified counsel; this document does not make legal determinations.
- Secrets: provider keys server-side only; rotation plan.
- Logs must not contain content; audit trail without content.
- Insider/admin access to user data: define policy and access logging (OQ-14).

## I. Unknown Requirements
Expected user count; support for multiple resumes per session (assumed one); session sharing/export needs; mobile/web-only live mode; offline behavior; billing/quotas per user; admin tooling; analytics; accessibility standards; UI branding; notification/email needs; exact answer-quality acceptance criteria.
